## 2. 第一性原理

### 2.1 读者任务

读者打开 L1-02 时，真正要完成的是下面这条链路：

```text
我现在是什么场景？
    ↓
这次开不开爆发？
    ↓
开了能换回多少价值？
    ↓
技能顺序要改什么？
    ↓
这在真实路线和真实日志里成立吗？
```

页面五段在内容上已经遵循这条链路，但视觉上五段几乎同权。结果是：

- 逻辑顺序存在；
- 视觉顺序不存在；
- 读者必须靠阅读才能重建优先级。

### 2.2 视觉必须编码的三件事

1. **先后**：结论先于解释，解释先于证据。
2. **轻重**：一个主判断，一个主数字，一个主动作；其余内容退后。
3. **可查**：需要深挖时，目录、折叠、悬停和状态必须让读者知道还能往哪里走。

任何视觉方案如果不能同时改善这三点，只是在换颜色和圆角。

### 2.3 当前问题的根因

| 根因 | 当前表现 | 后果 |
| --- | --- | --- |
| 没有明确的页面焦点 | 标题、三张顶图卡、第一段图同时争夺注意力 | 首屏无法快速回答“这波开不开” |
| 五段使用同一外壳 | 相同的 `h2`、边框、留白和说明句 | 核心判断与证据附录看起来同等重要 |
| 字号梯度不足 | 桌面仅 `30/21/14/12`，移动 `h1` 又降到 `21` | 标题、区块标题和卡片标题的差异不够强 |
| 节奏只有一种间距 | 段内 `14px`，段顶 `24px`，缺少更大的页面级呼吸 | 长页像连续文档，而不是分幕界面 |
| 容器宽度单一 | 720px 单栏同时承担正文、图、表和导航 | 宽屏空间没有被组织成产品结构 |
| 交互不可发现 | 路线点、折叠、目录、筛选多为小字或弱图形 | 用户把可操作界面误认为静态报告 |

## 3. 实测对照

### 3.1 数值

| 项 | 当前项目 | WowCoach 实站 | 判断 |
| --- | --- | --- | --- |
| 桌面内容结构 | 720px 单栏 | 1440px 视口内左右分栏、内容容器与视觉主件并列 | 不照搬双栏营销结构；章节页需要至少“目录 + 正文”的宽屏骨架 |
| 桌面 H1 | 30px / 800 | 54.4px | 章节页不需要 54px，但 30px 不足以形成强首屏 |
| 桌面 H2 | 21px / 700 | 36px | 参考差异说明区块级标题可以更有分量 |
| H3 | 14px / 600–700 | 20 / 18px | 当前没有真正的“图表标题层” |
| 正文字号 | 14px / 1.65 | 约 16–18px | 14px 可保留为数据密集正文，但说明文字不能继续只靠 12px |
| 说明文字 | 12px / muted | 正文与辅助层级明显分开 | 12px 应只做 caption，不再承担解释句 |
| 420px H1 | 21px | 36px | 移动端把主标题降成正文级，层级明显塌陷 |
| 主操作 | 章节页没有持续可见的主操作 | 首屏存在一个高对比主 CTA | 本项目应有一个“当前判断 / 下一步”锚点，而不是营销 CTA |

### 3.2 WowCoach 可迁移原则

#### 采用

- 首屏只建立一个主主张；
- 文案区与视觉区分工清楚；
- 主操作与次级操作有明显层级；
- 大区块之间留出页面级空白；
- 产品自身图形作为视觉锚点，不用无关插图。

#### 改造后采用

- 将“左侧说明、右侧产品演示”改为“左侧当前波次与判断、右侧价值与行动”；
- 将营销 CTA 改为“开 / 看冷却 / 不开”的决策锚点；
- 将产品演示改为真实路线小图、爆发价值和目标档卡片；
- 移动端保留 36px 左右的主信息量，不把章节 H1 降为 21px。

#### 明确拒绝

- 价格、注册、付费标签和营销 CTA；
- 54px 营销型 H1；
- 大面积装饰性外发光；
- 用虚构界面截图撑视觉；
- 为了“像产品”而新增账号、收藏、评论等功能。

### 3.3 Wowhead 可迁移原则

Wowhead 同页正文镜像包含 34 个二至四级标题、74 个技能图标和 74 个技能链接。可确认的组织方式不是“靠一张长卡片讲完”，而是：

- 大类下面继续分组；
- 同类条目使用稳定、重复的行结构；
- 图标和文字共同承担识别；
- 名称链接到独立详情，页面之间可以跳转；
- 长页面天然需要目录和当前位置感。

#### 采用

- 章节页增加五项目录与当前位置；
- 图表标题独立成层；
- 技能、条件和原始 APL 有清楚的展开层级；
- 同类信息保持同构，减少每章一套视觉；
- 图标/形状辅助识别，不只靠颜色。

#### 明确拒绝

- 旧式超高密度全量铺开；
- 每个条目都套卡片；
- 广告和站外推荐；
- 未经核对就复制站外技能名、图标语义或版本结论。

## 4. L1-02 的设计命题

### 4.1 主判断

> 这是 10–22 只怪的大波；默认开爆发，并让虚空齐射提前、精神鞭笞和暗言术：痛后移。

这不是新增文案，而是把现有 claim、rule 和 priorityDiff 在视觉上组织成一条可执行判断。

### 4.2 首屏层级

| 层级 | 内容 | 视觉职责 |
| --- | --- | --- |
| 1 | 章节身份：L1 / 大波 / 10–22 只 | 我在哪里 |
| 2 | 主判断：开 | 我该怎么做 |
| 3 | 主价值：一次爆发增量与目标档 | 为什么 |
| 4 | 主图或路线缩略图 | 我看到了什么 |
| 5 | 目录与阅读进度 | 还能看什么 |

### 4.3 桌面骨架

桌面章节使用“目录 + 宽主栏”外壳；正文和图表分别受不同宽度约束：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：当前专精 · 学习 / 解析台                               │
├───────────────┬──────────────────────────────────────────────┤
│ 200px 目录     │ 1168px 主栏（正文 36em / 图表全宽）          │
│               │                                              │
│ 01 场景        │ L1 / 大波（≥10 只）                          │
│ 02 爆发价值    │ 一句主张 + 场景摘要                           │
│ 03 技能调整    │                                              │
│ 04 路线位置    │ ┌───────────────┬──────────────────────────┐ │
│ 05 真人对局    │ │ 当前波次与模型 │ 开爆发 · 价值 · 行动      │ │
│               │ └───────────────┴──────────────────────────┘ │
│ [证据摘要]     │ 真实路线小图 / 波次带                         │
│               │                                              │
│               │ 五段正文                                     │
│               │                                              │
│               │ 证据条                                       │
└───────────────┴──────────────────────────────────────────────┘
```

约束：

- 目录与正文间距 24px；
- 正文保持 36em，图表和卡片使用主栏全宽；
- 目录只在 ≥1280px 出现；
- 目录不是装饰，必须可跳转并高亮当前段；
- 窄屏完全移出 DOM 布局，不压缩正文。

### 4.4 顶图带重构

三张等宽卡片是当前“模板感”最强的结构之一。下一版不再三卡等权：

```text
┌────────────────────────────────┬────────────────────────────┐
│ 当前波次                        │ 开爆发                     │
│ 10–22 只 · 30 秒 · 3 个危险点   │ +44.0% · 一次 +12.7M       │
│ 路线第 1 波 · 大波              │ 冷却够就开                 │
│ [真实路线/波次小图]             │ [金色行动面]               │
└────────────────────────────────┴────────────────────────────┘
```

- 左侧 7 份：场景、目标数、时长、危险点、路线位置；
- 右侧 5 份：行动结论、增量、一句读法；
- 右侧只使用一个高对比行动面；
- 路线小图承担本项目自己的视觉识别，不使用通用装饰 illustration；
- 原有 420px 顺序冻结为兼容冒烟，不再参与本轮桌面视觉目标。

### 4.5 五段的视觉层级

| 段 | 层级 | 视觉处理 |
| --- | --- | --- |
| ① 这一档有多大 | 主 | 大图 + 主数字；说明句不超过两句 |
| ② 开爆发值多少 | 主 | 开 / 不开对照图占主宽度，增量单独成视觉数字 |
| ③ 技能顺序怎么改 | 执行 | 加 / 降两组，用行而不是多张同构卡 |
| ④ 落在路线哪里 | 情境 | 地图与路线带偏宽，允许比正文宽 |
| ⑤ 真人怎么打 | 证据 | 结论和时间轴保留；方法与限制默认折叠 |

视觉必须让“②决定是否开”和“③决定怎么打”强于“⑤事后核对”，不能五段同样醒目。

### 4.6 字样与节奏

| Token | 目标 |
| --- | --- |
| display | 36px |
| title | 24px |
| sub | 18px |
| body | 16px |
| meta | 14px |
| caption | 12px |

规则：

- 12px 只做图注、chip、刻度和原始记录；
- 读者需要阅读的解释句使用 16px 和次级正文色；
- 表格、标签和次要元信息使用 14px，不再使用 12px 承载解释句；
- 字体权重收敛到 400 / 500；
- 正文行高 1.75；标题行高 1.20–1.45；
- 说明与结论使用 `36em` measure，16px 正文下约 576px；
- 图表和表格可以保持 720px，不跟着正文收窄。

间距规则：

| 层级 | 值 |
| --- | --- |
| 组件内部 | 8 / 12px |
| 段落内部组之间 | 16px |
| 五段之间 | 32px |
| 页面大区块之间 | 32px |
| 顶图带下 / 证据条上 | 48px |

### 4.7 交互与状态

首版视觉样板只加入有真实用途的交互：

- 五项目录跳转与当前段高亮；
- 真实路线选波；
- “9 段阶段明细”折叠；
- “方法、限制”折叠；
- “查看原始记录”折叠；
- `focus-visible`；
- `prefers-reduced-motion` 降级。

不增加收藏、评论、账号、标签、相关推荐和虚构 loading 状态。

## 6. 验收指标

视觉样板必须同时通过内容和界面两类验收。

### 6.1 首屏

- 1440×1000 下，首屏能同时看到：章节身份、主判断、主价值、主图或路线缩略图。
- 420×900 下，第一屏先出现主判断和主价值；路线图排在行动内容之后。
- 首屏只有一个最强行动面，不再让三张同权卡片同时抢焦点。

### 6.2 层级

- computed 字号只来自六档；
- computed 字重只来自 400 / 500；
- 五段至少有三级视觉强度，不再全部同权；
- 说明文字落入 max-width `36em`；
- 一个概览视口内只出现一个高饱和实底主操作。

### 6.3 桌面布局与冻结兼容

- 桌面验收使用 1280 / 1440 / 1920；1440 下页面和章节壳左右留白不超过 24px；
- 移动端不再作为设计目标，420px 只保留 `scrollWidth ≤ clientWidth` 的冻结兼容冒烟；
- 关键按钮和目录触控目标 ≥44px；
- 目录只在 ≥1280px 出现；
- 键盘顺序与视觉顺序一致；
- 减少动效设置生效。

### 6.4 内容红线

- 不新增没有来源的数字；
- 不修改 claim、casePanel、runId、原始 APL 和图契约状态；
- 正文可见文本不含 Markdown 标记；
- 原始证据展开后仍完整。

## 7. 实施顺序

1. **先完成本拆解评审**：确认参考权重与 L1-02 视觉命题。
2. **L1-02 第一轮可运行样板**：已通过默认关闭的 `ReaderRefreshContext` 隔离。
3. **对比 1440 / 1024 / 1920 桌面截图**：已接入门禁；420px 只保留冻结兼容冒烟。
4. **用户验收后再改全局 token**：字号、间距、暗色和字体栈一次性同步。
5. **按层级铺开**：6 个 L1 与 L2 已复用验收后的目录、决策顶图带、证据折叠和阶段结构；L0 继续保留基础章节结构。
