# 第一性原理：别的教程在做什么，我们缺什么

> 用途：给"下一批该补什么"排序。不是竞品观感对比，是把教程拆到约束层再对账。

---

## 1. 拆到底：什么让一次判断值 DPS

一次判断要能换成伤害，只受四个约束支配，缺一个都判不了：

| 约束 | 说的是什么 | 典型失效问法 |
| --- | --- | --- |
| **① GCD 时间预算** | 这一波总共只有约 N 个 GCD，任何动作都在抢它 | "这个技能要不要打"——打它就少一个别的 |
| **② 资源收支** | 狂乱值产出 vs 消耗；冷却的可用窗口 | "狂乱值要溢出了吗" |
| **③ 目标放大** | 多目标时 DoT / 爆发 / 心智联接的放大倍数 | "这个技能强不强"——强不强取决于几只怪 |
| **④ 机制风险** | 移动、打断、驱散、致死各吃掉多少时间/资源 | "要不要躲"——躲的代价是几个 GCD |

一句话：**DPS ≈（② 资源转化效率 × ③ 目标放大）÷ ① 时间成本，再扣 ④ 的损耗**。
所有"该不该开爆发""该先打哪个"都能落到这四个量上；落不上的，都是话术。

## 2. 其他教程默认了什么

它们面向"已经稳定输出、只缺顺序"的读者，所以交付的是**清单 + 阈值 + 权威**：

- 只给一条顺序（少数给 AoE 一套），不区分"这一波几只""这段能活多久"；
- 阈值给得很硬（"<20% 打灭"），但不给阈值从哪来；
- 装备给固定权重表（Pawn / 血槌），一个数字吃遍所有场景；
- 版本一换，上一版的结论直接替换，不标哪些会变、哪些不会；
- 分歧不处理：A 站说第 6 位、B 站说第 12 位，读者自己猜。

优点也要认：**它们可查、可引用、覆盖面大**。我们的短处不在"讲得对不对"，在"读者拿不到一条能引用的原文链"。

## 3. 对账：我们有什么、缺什么

| 约束 | 现有资产 | 覆盖度 | 缺口 |
| --- | --- | --- | --- |
| ① GCD 时间预算 | 5 个动作 trace（2 / 4 / 5 / 8 目标与 BOSS 90s）；动作按 DoT / 填充 / 爆发 / 物品拆分；GCD 起手点按起始时间去重；L1-05 另有观测冷却窗口 | **已覆盖全部 L1** | 还是木桩满 uptime：走位、转火、打断没有折算；L1-05 的具体两波间隔仍需 Fights/死亡事件 |
| ② 资源收支 | 上述 5 个 trace 的逐动作狂乱采样；APL 38 条、爆发与冷却 A/B | **采样收支已覆盖** | 只有动作采样，不是事件级跳数；无触顶采样，溢出量仍未量化；两波窗口是 C 层算术，不是连打模拟 |
| ③ 目标放大 | L1-01…L1-06 六个波次模型、L2-01 路线逐波、解析台联动、4 输出模型配装；2/5/6/7/8 目标爆发增量与每多 1 只的边际 | 主结论覆盖 + 边际已算（5→6 +1.16M、6→7 +1.09M、7→8 +1.16M） | 杠杆只有单体 300s / 5 目标 30s 两档，缺同一技能跨全部模型的边际对照 |
| ④ 机制风险 | 波次模型里只有「危险点 N 个」 | **空白** | 当前路线 14 波的 `dangerous` 为空，没有机制时间戳；不解释打断/驱散/移动各吃几个 GCD、值多少 DPS |
| 装备侧 | 本次新增：属性/附魔/消耗品/饰品 × 4 输出模型 | 覆盖 | 缺"换一件装备"的增量（当前是"摘掉"口径） |
| 来源可信度 | 4 家原文 md + crosscheck + 本次新增参考资料页 | 覆盖 | 英雄天赋机制只有原文支持，未单独跑批 |
| 版本迁移 | 无 | **空白** | 缺"换版本哪些结论会变"的敏感性清单 |

## 4. 补的顺序（按"每个缺口能换回多少判断力"排）

1. **装备侧**（已做）：属性权重随输出模型变化，这是其他教程最不可解释的一块，我们能用 runId 直接摊开。
2. **参考资料页**（已做）：补上"可引用"这一条，读者能顺着原文链接核。
3. **GCD 时间预算 + 资源收支卡**（已做 5 章）：用 trace 动作序列算账——2/5/8 目标 30 秒分别有 39/39/37 个 GCD 起手点、间隔中位 0.755–0.757 秒；DoT、填充、爆发、物品各占几个动作，狂乱采样峰值与消耗次数同图。L1-05 的两波窗口仍缺，不用 300 秒木桩硬凑。
4. **机制机会成本**（有来源再做）：把打断/驱散/移动折算成 GCD 与 DPS 两种单位，落到具体副本机制上。当前路线 `dangerous` 为空，先补机制时间来源。
5. **版本敏感性清单**（可选）：列出"换版本会变的数"（套装、APL 条件、属性权重）与"不会变的判断"（先光晕再爆发这类顺序约束）。

## 5. 怎么算补上了

- 每条结论旁边都能指到 runId（模拟）或 logId（日志）——现有门禁 `validate:content` 已在拦。
- 新增的每一页都有一张**能算的数**，不是一张流程图：GCD 卡要给出"这一波 N 个动作"，机会成本要给"躲一次 = 少 X% DPS"。
- 与其他教程的差异要写在页面上（哪句一致、哪句我们不同意、依据是什么），而不是留在口头。
