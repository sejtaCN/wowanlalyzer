**层级规则**

| 规则 | 说明 |
| --- | --- |
| L0 只有一层 | 顶栏是唯一的全局导航，只有一个可切换维度（专精） |
| L1 共 4 个屏 | 首页 / 章节页 / 解析台 / 未实装专精。**章节页不是并列的导航项**——它是首页的下钻 |
| L2 是「段」不是「页」 | 章节页内的 ①②③④⑤ 是页内分区，不是可跳转的页面（除 L2 副本页的选波） |
| 跳转一律单向 | 章节页 → 首页（面包屑 / 面包屑返回）；**没有章节页之间的横向跳转**（相关推荐 M26 未做） |
| 解析台是「旁路」 | 不在学习动线上，从顶栏直达，**不打断章节页的叙事**（这正是 B 批把 tab 改成纵向六段的原因） |

### 1.3 三个导航域

| 域 | 屏幕 | 语气 | 密度 | 用户心理 |
| --- | --- | --- | --- | --- |
| **学习域** | 首页 + 章节页 | 教学、结论先行 | 中 | 「我在学怎么打」 |
| **数据域** | 解析台 | 工具、表格密集 | 高 | 「我要自己挖数据」 |
| **元层** | 未实装专精页 | 工程、诚实 | 低 | 「这个还没做完」 |

**这三域必须看起来像同一个产品但语气不同**——目前它们共享同一套 token，所以颜色、圆角、间距已经统一；**问题出在文案语气没有分层**（元层的工程黑话渗进了学习域，见 `ui-refresh-plan.md` §3.2）。

## §3 统一设计语言

### 3.1 色彩体系

**原则**：暗色不是亮色的反转。表面靠**步进亮度**分层，投影不用（暗底上投影不可见），层次靠「更亮的表面 + 低透明度描边」表达（R5）。

#### 3.1.1 表面阶梯（步进 +6% 亮度）

| Token | 现值 | 建议 | 对比度（对 `--bg`） | 用途 |
| --- | --- | --- | --- | --- |
| `--surface-base` | `#0b0e13` | `#0b0e13` | — | 页面底 |
| `--surface-1` | `#0f1420` | `#0f1420` | — | 卡片 |
| `--surface-2` | `#141a26` | `#141a26` | — | 卡片内嵌块 / 表头 |
| `--surface-3` | `#1a2130` | `#1a2130` | — | 悬停态 / 浮层 |
| `--surface-4` | *（无）* | `#212938` | — | 弹层 / 下拉（新增） |
| `--border-subtle` | `#262b36` | `#262b36` | — | 分隔线 |
| `--border-strong` | `#333b4a` | `#333b4a` | — | 强分隔 / 悬停描边 |

> 刻意**不用纯黑 `#000`**（R5：纯黑 + 纯白会造成光渗与眼疲劳）。

#### 3.1.2 文字阶梯

| Token | 现值 | 对比度 | 用途 | **禁用** |
| --- | --- | --- | --- | --- |
| `--text-primary` | `#f8fafc` | 18.9:1 | 标题、结论、关键数字 | — |
| `--text-secondary` | `#b8c2d0` | 10.9:1 | **正文说明句**、表格主内容 | — |
| `--text-muted` | `#94a0af` | 7.2:1 | 图注、刻度、元信息 | **不用于承载结论** |
| `--text-disabled` | *（无）* | `#5b6675` | 禁用态、占位 | — |
| `--text-on-accent` | *（无）* | `#1a1400` | 金色实底上的文字 | — |

> **关键修正**：现状把大量**说明句**放在 `--text-muted` + 12px。说明句是读者要读的内容，必须用 `--text-secondary` + 13px。`--text-muted` 只留给图注、刻度、chip。

#### 3.1.3 语义色

| Token | 现值 | 语义 | 硬性规则 |
| --- | --- | --- | --- |
| `--accent` | `#f5c451` | **唯一强调色**：结论、主行动、当前下一步 | 一屏内金色实底只允许 1 处（顶图带右格「该做什么」） |
| `--accent-soft` | `rgba(245,196,81,.12)` | 金色底纹 | 标签底、选中态底 |
| `--positive` | `#4ade80` | 提升 / 开爆发 / 显著 | — |
| `--negative` | `#f87171` | 下降 / 掉 DPS / 亏损 | — |
| `--warning` | `#fbbf24` | 边界提示、限制说明 | 与 `--accent` 太近，**只用于「限制」条**，不用于结论 |
| `--info` | *（无）* | `#60a5fa` | 新增：链接、折叠区展开提示 | 站内唯一可用的蓝 |
| `--neutral-bar` | `#46505f` | 图中的「对照组」（不开爆发） | 图表专用，不可做文字 |

**颜色语义决策（重要）**：本站是游戏攻略，**不是金融**。红/绿表示「伤害收益」而非「价格涨跌」，沿用 WoW 社区通用约定：**绿 = 有增益 / 开爆发 / 显著提升，红 = 掉 DPS / 亏损 / 不该做**。全站不出现涨跌语境的颜色编码，故不适用中文股市「涨红跌绿」。

**禁用**：`--accent` 不做装饰（不用于边框、图标底、hover 底）；`--positive`/`--negative` 不做大于 14px 的文字色（对比度虽够，但会喧宾夺主）。

### 3.2 字体与字重

| Token | 值 | 用途 |
| --- | --- | --- |
| `--font-sans` | `system-ui, -apple-system, 'Segoe UI', 'PingFang SC', 'Microsoft YaHei', 'Noto Sans SC', sans-serif` | 正文 |
| `--font-mono` | `ui-monospace, 'Cascadia Mono', 'SF Mono', Consolas, monospace` | 数字、runId、路径、命令 |

> **删掉 `Inter`**：现状 `ui.css:53` 声明了 `Inter` 但从未加载（无 `@font-face`、无外链），实际落到系统字体。声明一个不存在的字体是误导。

**字重只用两档**（R4/R5 的共识）：`400` 常规 / `500` 中等。现状 `ui.css` 用了 600/700/800 三档（`h1` 800、`h2` 700、`h3` 600），在暗底上过重。**改为 500**，靠字号与颜色拉开层级。

### 3.3 字号与行高（6 档）

| Token | 值 | 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| `--fs-display` | 36px | 1.20 | 500 | 页面主标题（每页 1 次） |

> **同步项**：`scripts/check-ui.mjs` 的 `FS_OK` 已同步为 `36/24/18/16/14/12`，并增加全局 CSS token、字重、行长和桌面宽度断言；420px 仅保留冻结兼容冒烟。

| `--sp-9` | 64px | 页面级留白 |

外加一个**语义值**（不参与相邻比检验）：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--gap` | 16px | 段内图间距（被 `check-ui.mjs` 断言） |

> **为什么是 9 档**：原设计稿只有 5 档（4/8/14/24/40），实施时发现下半段太粗——段内元素极密（表格单元、图例、chip），4/8/12 会让紧凑场景无处落脚，遂补 2/4/8/12/16/32/48/64。

> 全局落地后，五段之间为 32px，段内图为 16px，顶图带下和证据条上为 48px，组内与组间层级已经分开。

### 3.7 卡片规范

```
┌────────────────────────────────────────────┐
│ 卡片标题（--fs-sub 17px / --text-primary）  │  ← 只有标题和结论用大字
│ 副标题或状态标签（--fs-caption 12px chip）   │
├────────────────────────────────────────────┤
│  内容区（图表 / 表格 / 正文）                │
│  内边距 --sp-4 24px                         │
├────────────────────────────────────────────┤
│ 说明句（--fs-meta 13px / --text-secondary） │  ← 图注区，不是正文
│  最多 2 句，超出折叠                        │

```

**卡片高度分级**：图卡（≥160px）、表卡（内容自适应）、提示卡（≤80px，只有一行说明）。

### 3.8 表格规范

| 规则 | 规格 |
| --- | --- |
| 表头 | `--surface-2` 底、13px、`--text-secondary`、字重 500、**不缩放**（保持 13px 可读） |
| 单元格 | 13px、`--text-primary`；数值列 `--font-mono` + `tabular-nums` + **右对齐** |
| 行高 | `padding: 8px 12px`，行间 1px `--border-subtle` 分隔；**不用斑马纹**（暗底上斑马纹噪） |
| 排序/筛选态 | 保留现状：解析台⑥ 前缀筛选框 |
| 溢出 | 横向滚动容器 `.tblwrap`，**允许**横向滚（表格信息密度高，压缩列宽会更难读） |
| 数值强调 | 只在「这一行的结论数字」上用 `--accent`；其余数值一律 `--text-primary` |

### 3.9 图标风格

- **线性图标，1.5px 描边**，尺寸 16 / 20 / 24 三档（16 用于行内，20 用于按钮，24 用于区块）。
- 颜色跟随文字色（`currentColor`），**不单独设图标色**（R5：图标色必须跟着状态走，硬编码 hex 会失控）。
- 暗底上纯白图标过刺眼 → 线性图标用 `--text-secondary`。
- **本站目前零图标**，全部用文字/符号（`›` `▾` `★` `→`）。本次**不新增图标库**（避免为 3 个图标引入依赖），统一用几何符号 + `currentColor`。
- 状态点（`.statusdot`）：绿点 = 已实装，灰点 = 筹备中，8px 圆。

### 3.10 交互状态

| 状态 | 规格 |
| --- | --- |
| hover | 背景升一级表面（`--surface-1` → `--surface-2`）；**不用缩放**（R8 的"卡片放大"在密集信息页会抖） |
| active / pressed | 背景再升一级；**120ms ease** |
| focus-visible | `outline: 2px solid --accent` |
| selected | 金色 `--accent-soft` 底 + `--accent` 描边 |
| disabled | `opacity: .45`，`cursor: not-allowed` |
| loading | 骨架屏用现有 `components/Teaching/Skeleton.tsx` 的灰模，**不用旋转菊花** |
| 空态 | **给形状不给形容词**（`writing-style.md` §5）：画出将来长什么样 + 缺什么 + 3 步内怎么补 |

| 路由切换 | 滚动回顶（现状已有 `window.scrollTo`） |

### 3.11 文案语气

### 三条铁律

1. **写「怎么做」，不写「怎么做的」**——不描述实现过程。
2. **一句话只做一件事**——禁三段式并列（结论+补充+免责）。
3. **读者不关心代码**——内部标识符（runId、APL 表达式、文件路径、批次号）不进正文。

### 语气基准（站内已有高质量样本，**不改**）

> 「三段都是持续 3 分钟以上的多目标区。大波值钱，但真正的条件是"这一段够长、能吃到第二次冷却"。」——`l1-02-large.json` `casePanel.reading`

句式特征：短句、数据在前、有一句转折判断、不解释为什么这么写。

### 三域语气差异

| 域 | 人称 | 允许的术语 | 禁止 |
| --- | --- | --- | --- |
| 学习域 | 第二人称「你」 | DPS / APL / GCD / CI / DoT（首现挂悬停） | runId、APL 表达式、文件路径、"我们可以看到"、"注意"、"尽量" |
| 数据域 | 无人称 | 上述全部 + 场景 id（但用中文描述如「8 只 / 30 秒」） | "本页不引用模拟"这类自述 |
| 元层 | 无人称 | 脚本名、路径、命令（**这页就是给开发者看的**） | 混进学习域 |

### 术语三分类（详见 `ui-refresh-plan.md` §3）

- **L1 保留英文**：DPS、APL、GCD、CI、DoT、N+1
- **L2 中文化**：runId→模拟记录、SimC→模拟器、Jaccard→重合度、commit→版本号
- **L3 移出页面**：APL 表达式、英文技能键、场景 id、文件路径、批次号、门禁/跑批

### 中文排版细则（W3C clreq）

| 规则 | 落地 |
| --- | --- |
| **汉字与西文之间加 1/4 汉字宽间距**（R6） | 正文 CSS `text-spacing-trim` / 手动在混排处插 `&thinsp;`；或用 `text-autospace`（Chrome 137+ 已支持） |
| **行首行尾禁则**（点号、结束引号不出现在行首） | `line-break: strict`（默认即生效）；全局禁止 `word-break: break-all` |
| **西文单词不跨行断开** | 全局 `overflow-wrap: break-word`（不是 `anywhere`，避免把单词切碎）；长路径类用 `break-all` 局部放开 |
| **标点挤压**（连续标点占 1.5 字宽） | 浏览器原生支持，**不要用 `font-feature-settings` 关掉** |
| **孤行寡行**（段落末行不单字成行） | `text-wrap: pretty`（Chrome 117+）；标题尤其需要 |
| **正文行长** | 30–45 全角字（见 §4.3 measure） |
| **汉字标签不加字距** | 中文标签禁用正 `letter-spacing`——汉字是等宽方块字，加字距是在字与字之间插空隙，破坏行末对齐与标点挤压。强调改用**字重 + 颜色** |
| **汉字标签不用 uppercase** | `text-transform: uppercase` 对汉字完全无效，留着只是误导（读代码的人以为它在起作用）。整段是西文时才可保留，且应单独建类 |
| **负字距保留** | `h1`/`h2`/`.brand` 的负 `letter-spacing` 有效——收紧字距在中文里同样减少松散感，且不会撑开字距 |

> 后三条是**本项目独有**的规则。Refactoring UI 与 Hallmark 都基于拉丁字母，没有 CJK 处理：Hallmark 甚至把「带字距的全大写标签」列为 Floor 级禁止项——那条规则对中文是误判，但指向的视觉问题在中文里同样存在，只是成因不同。详见 `docs/design-rules.md` §4。
>
> 已落地：9 处中文标签的正字距与 9 处 `uppercase` 全部清除，3 处负字距保留。由 `npm run check:design` 强制。

### 4.5 未实装专精页（元层）

**这是工程页**，允许出现路径与命令——但语气要对读者诚实。

```
┌────────────────────────────────────────────────────┐
│ 面包屑：← 学习 / 猎人 / 恶魔猎手                     │
├────────────────────────────────────────────────────┤
│ kicker：数据筹备中 · 界面已就绪                       │
│ H1 恶魔猎手 · 噬灭 / 歼灭者                          │
│ 副标题：页面模板已就绪，前四步数据待补。补齐后页面自动长出来。│
├────────────────────────────────────────────────────┤
│ 流水线（5 步，横向）                                  │
│  专精配置 → 模拟跑批 → 分析 → 章节稿 → 页面          │
│  每步：名称 + 副说明 + 状态 chip（待配置/待跑批/…/已就绪）│
├────────────────────────────────────────────────────┤
│ 「接上数据之后，长这样」—— 3 张灰模                  │
│  章节页 / 副本页 / 解析台，各配一句 caption            │
├────────────────────────────────────────────────────┤
│ 「还差什么」—— 4 步表（做什么 / 产出什么 / 放哪）      │
├────────────────────────────────────────────────────┤
│ 提示行：想看填满的样子：切回暗影牧师                   │
└────────────────────────────────────────────────────┘
```

**灰模规范**（借 R2 的「每步一卡 + 状态标记」）

| 元素 | 规格 |
| --- | --- |
| 灰模块 | `--surface-2` 底、1px **dashed** `--border-strong`、圆角 16px |
| 灰模行 | 高 10px、圆角 3px、`linear-gradient(90deg, #2b3444, #202836)`（现状已是） |
| 状态 chip | 已就绪=绿 / 待配置·待跑批·待分析·待成稿=灰 |
| caption | 13px `--text-secondary`，**只说这张图回答什么问题** |

**命令列**：等宽 12px，`--surface-2` 底，**保留路径与命令**（这页就是给开发者看的，是 §3.10 允许 L3 的唯一例外）。

**断点**

| 断点 | 范围 | 变化 |

**移动端硬指标**

| 指标 | 要求 |
| --- | --- |

### 6.4 设计门禁（新增 `scripts/check-design.mjs`）

规则来源与适配说明见 `docs/design-rules.md`。跑在源码上，不需要浏览器。

| # | 断言 | 规则来源 |
| --- | --- | --- |
| G1 | 间距阶自身合规：相邻档差 ≥ 25% | Refactoring UI §3.2.2 |
| G2 | `padding`/`margin`/`gap` 的裸 px 值全部落在间距阶内 | 同上 |
| G3 | token 块外不得出现 hex 色值（TSX 内联色值同样禁止） | Refactoring UI 法 3 / Hallmark gate 48 |
| G4 | token 推出的 21 组前景/背景配对，对比度 ≥ 4.5:1 | Refactoring UI §5.6 / WCAG |
| G5 | 中文标签禁用正 `letter-spacing`（px/em/rem 都算） | 本项目独有（clreq） |
| G6 | 中文标签禁用 `text-transform: uppercase` | 本项目独有（clreq） |
| G7 | 必须存在 `:focus-visible` 样式 | WCAG 2.4.7 / Hallmark gate 26a |
| G8 | 有动效必须有 `prefers-reduced-motion` 兜底 | WCAG 2.3.3 / Hallmark gate 27 |
