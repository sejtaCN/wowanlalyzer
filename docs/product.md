# 产品定义（唯一真源）

> 本文件取代此前所有产品描述：`product-contract.md`、`plan-v2.md` 里的课程结构与界面部分、
> `requirements.md`、`learning-system.md` 的旧章节。冲突时以本文为准。
> 最后确认：2026-10-25

---

## 0. 适用范围（2026-10-26 更新）

界面按**多专精**设计：当前只实装暗影牧师的执政官；虚空编织者保留为后续数据待补，
其他专精（如恶魔猎手·噬灭·歼灭者）已在注册表里占位，切过去看到的是"骨架预览"，标明缺什么数据。
产品名改为中性的「专精学习系统」，当前专精由顶栏选择器显示。

## 1. 一句话

**一个暗牧（暗影牧师）的看图学输出的地方**：不用装 SimC、不用传日志，也能学会
「这一波该怎么打、爆发该给哪一波」；想深挖时，再把你的日志接进来。

## 2. 用户

| 用户 | 他有什么 | 他要什么 |
| --- | --- | --- |
| 零基础玩家（默认） | 没有 SimC、没有日志、不知道自己该看什么 | 能照着图打出不丢人的循环，知道爆发什么时候开 |
| 进阶玩家 | 有 WCL 记录 | 想知道自己哪一波打错了、差多少 |
| 高手对照 | —— | 别人为什么这么打（有数据支撑，不是玄学） |

## 3. 教学主线（一条，不可改）

```
知识讲解 → 可视化解析 → 高手案例 →（可选）个人复盘
```

- 「可视化解析」= 看图看数，**不是答题**。产品内不再有选择题、任务清单或记录框。
- 前三步不依赖任何导入；复盘才需要日志。
- 数据永远是"可选增强"，不是准入门槛。

## 4. 教学内容怎么组织（这是本轮最大的改动）

**不按"第 1 课、第 2 课"线性排**。按 **层级 + 波次模型** 组织，因为玩家真正的问题是
「这一波该怎么打」，不是「第 5 课讲什么」。

```
L0 基础（4 页，全局共用，只讲一次）
   0.1 暗牧在做什么（资源 + 持续伤害两根轴，一页讲完）
   0.2 技能清单（技能卡：中文名 / 人话 / 资源 / 冷却 / 类型）
   0.3 优先级表（38 条，条件 + 选目标，来自 APL）
   0.4 爆发与冷却（Voidform / PI / 药水 / 饰品，谁等谁）

L1 波次模型（核心，6 章；每章结构固定，见 §5）
   1.1 中波（5–9 只）
   1.2 大波（≥10 只）
   1.3 小波（≤4 只）
   1.4 BOSS（单体 / 阶段）
   1.5 节奏型：大波后的小波
   1.6 ADD 型（波内持续加怪；用窗口近似并标注）

L2 副本实战（每个副本一页，把 L1 的模型套到具体路线）
   2.1 Altar of Fangs（毒牙祭坛）：14 波 → 标模型类型 → 爆发分配 + 地图
```

三层的价值：**L0 只学一次；L1 可以跨副本复用；L2 是当版本的具体答案。**
新副本来，只加 L2 一页，不用重写课程。

## 5. 一个页面的固定结构（L1 / L2 都一样，五段，顺序不变）

| 段 | 内容 | 数据来源 |
| --- | --- | --- |
| ① 模型卡 | 目标数 / 存活时长 / 移动与打断 / 危险点 | 路线（波次）+ 假设（时长） |
| ② 主图 | 这一波的**爆发价值**或**优先级差异**（一条结论 + 一张图） | 模拟 runId |
| ③ 技能调整 | 相对 L0 优先级表，这一波**加哪条、降哪条、为什么** | APL + 模拟 |
| ④ 地图 | 这一波在地图上的位置 + 前后两波的关系 | keystone.guru 瓦片 |
| ⑤ 高手对照 | 有日志就有，没有就写"待补"，**不编** | WCL 事件 |

固定结构的好处：用户学会一次就会读所有页；我们也只需要做一套渲染组件。

## 6. 数值与证据（红线）

1. **没有 runId 的百分比不许出现在页面上**。构建期扫描，查不到来源直接失败。
2. 每个 runId 必须带：SimC 版本 + commit + 迭代数 + 95% CI + 生成时间。
3. 引用别人的数据（如 Icy Veins 的结论）必须标出处，并且**不复制它的理由**——理由要有我们自己的证据。
4. 日志类结论必须能追到具体事件（时间戳 + 技能 + 目标）。切不出边界的（例如"这一波"），就写"切不出来"，不硬套。
5. 技能中文名必须核对过来源；未核对的保留英文 key，并在页面上标注。

## 7. 三个数据来源的定位

| 来源 | 用途 | 没有它时 |
| --- | --- | --- |
| SimC 模拟（我们跑） | 所有价值数字、波次模型、阈值 | 没有内容，这是刚需（在内容生产侧，不在用户侧） |
| keystone.guru 路线 | 波次构成、顺序、地图 | L2 退化为"通用波次模型"，L1 不受影响 |
| WCL 日志（事件表 CSV） | 高手案例、个人复盘 | ⑤ 段写"待补" |
| SimC 个人配置 | 只回答"你带了什么" | 一条说明，不影响任何页面 |

## 8. 明确不做

- 不做选择题、不做打分、不做"完成率"式激励。
- 不做整场 DPS 评分或排名。
- 不猜测版本、不猜测日志边界、不用示意数字冒充真实数据。
- 不因为导入的专精而改变学习目标（永远是暗牧）。
- 不做 CN 战网不支持的接入方式（WCL API 需绑定 Battle.net，CN 不可用 → 走事件表 CSV）。
