# 图契约与门禁（2026-10-26）

> 唯一图清单：`content/figures/chapters.json`。章节 JSON 只放内容，图有没有、缺什么、下一批补什么，都看这份清单。

## 1. 五段各有什么

每一章固定五段，契约也是五条：

| 字段 | 含义 |
| --- | --- |
| `section` | 1–5，必须与页面段号一致 |
| `kind` | 图类型，必须在该文件 `kinds` 白名单里 |
| `status` | `ready` 有真实图/表；`missing` 缺图；`not-applicable` 这一段本来就不该有图 |
| `source` | `ready` 必填：runId、logId 或路线文件；`missing` 也写清需要补什么 |
| `note` / `next` | 边界说明 / 缺图排到哪一批 |

`ready` 不代表四约束已经讲全，只代表这一段已有对应图形或表格。缺图归 `missing`，不得拿纯文字占位或一句说明冒充。

当前基线：11 章 × 5 段 = **55 段**，其中 **50 段有图、0 段缺图、5 段不适用**。原先缺图的 L0-03 与 L1-01 第⑤段已改用模拟动作时间线（`content/analysis/simulated-timelines-archon.json`），契约状态由 `missing` 改为 `ready`；时间线是模拟产物，不冒充真人日志阶段。缺图会重新出现在 `validate:content` 和 `check:ui` 的逐条警告里，不阻塞现有内容，但不能再被误报成“每段都有真图”。

## 2. 两道门禁各查什么

`npm run validate:content`：

- 每章契约必须 5 段、编号不能错位；
- 图类型必须在白名单；
- `ready` 必须有来源；
- `missing` 必须写下一批；
- 第②段图类型要与 `chapter.chart.kind` 一致（L2 的 `selected-wave` 例外）；
- 未知主图类型、契约缺章直接失败。

`npm run check:ui`：

- 先构建，再打开 `file://dist/index.html`，避免验到旧包；
- 从首页逐章点开 **11 章**，核对标题、桌面栏宽（壳 1392 / 正文 1168）、顶图带 3 格、五段、段标题和一句说明；
- 按契约逐个 `ready` 段找真实 DOM 图元（图、表、三步卡、时间轴等）；找不到就失败；
- 缺图只打印警告；`not-applicable` 不要求图；
- 截图逐章落到 `.tools/tmp/ui/chapter-<id>.png`。

## 3. 门禁自身要有坏样本

`npm run verify:gates` 现在是 23 项自检，分六组：

| 组 | 项数 | 正样本 | 坏样本 |
| --- | --- | --- | --- |
| 数据 / 图契约 | 2 | 原契约跑 `validate:content` 通过 | 临时把 L1-02 契约删成 4 段，必须失败并报「图契约必须有 5 段」 |
| 界面 | 4 | 原构建产物跑 `check:ui` 通过 | 把 `play-budget` 类名改坏、删掉 `evidence-raw` 折叠、给读法注入反引号，三种都必须点名失败 |
| 分析与配装 | 6 | 真实配装 / 属性产物通过 | 空对照、缺场景、弱对照、复现差、最优误差分别变红 |
| 相邻交换 | 5 | 真实 4 组交换逐项可复核 | 改差值、引用不存在的 runId、阳性对照被判无效、无效对照改回「误差内」分别变红 |
| 设计 | 2 | 还原后的 `ui.css` 通过 | 注入离阶间距 / 正字距 / `uppercase` / token 块外色值，逐条点名 |
| 文案 | 4 | 真实文案通过（ComingSoon 单列延期） | 比较句、纯英文机器串、可见 JSON 分别被点名 |

23 项全过，才算门禁不是空转。坏样本只写系统临时目录，不修改仓库内容；设计组的负样本要临时改 `ui.css`，用完必须还原。

## 4. 改图时的顺序

1. 先确定这一段回答什么、数据从哪来；
2. 在契约里把 `kind/source/status` 写对；
3. 实现图组件，给根元素加 `data-figure-kind`；
4. 页面段壳从契约取状态，不再手写“有图”；
5. 跑 `validate:content`、`check:ui`、`verify:gates`；
6. 状态确实变成真图后，才从 `missing` 改成 `ready`。
