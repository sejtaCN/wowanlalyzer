## 1. 三条原则

1. **一屏一个判断。** 首页回答"现在学哪个模型"；章节页回答"这一波怎么打、爆发给不给"；解析台回答"我自己的数据长什么样"。
2. **图先于字。** 每一段先给图或表，正文只解释图里读不出来的东西。任何一屏文字超过两屏高就是设计失败。
3. **结论必须可见地挂着证据。** 页面底部常驻证据条（runId / 来源 / 日期 / CI），点开看原始文件。

## 2. 信息架构

```
顶部：暗影牧师 · 学习  [首页] [解析台]        ← 只有两个入口
首页
├── 下一步（一张大卡：现在该看哪一章）
├── 三个入口：L0 基础 / L1 波次模型 / L2 副本实战
└── 底部：数据状态（模拟版本、日志有无、路线版本）
章节页（L1 与 L2 共用模板）
├── 面包屑 + 模型卡（①）
├── 主图（②）+ 技能调整（③）
├── 地图（④）+ 高手对照（⑤）
└── 证据条（常驻）
解析台
├── 数据源切换（模拟 runId / 日志 / 路线）
├── 价值矩阵、阈值曲线、时间轴
└── 每个数字点开看原始 JSON
```

导航只有 2 项，是因为 L0/L1/L2 是同一套模板的不同层级，不需要并列成三个模块。

## 4. 章节页（核心模板）

### 4.1 版式

```
面包屑：L1 / 大波（≥10 只）
──────────────────────────────────────────────
顶图带（三格，等宽）
  这一波长什么样      | 一条数字结论          | 该做什么
  10–22 只 · 30s      | +44.0% · 一次 +12.7M  | 10–22 只 › 30s › 开
──────────────────────────────────────────────
① 这一波几只、活多久     模型卡四个数字 + 目标数轴 +（有 trace）动作预算 + 三步判断
② 开爆发值多少           开 vs 不开双条（带 n / ±CI）；L0 换成优先级表 / 技能卡，L2 换成波次表
③ 这一波技能顺序怎么改   两列：这一波要加 / 要降，每条带 APL 行或 runId
④ 落在路线的哪一波       地图 + 逐波柱（横轴 = 第几波）+ 本章高亮
⑤ 真人怎么打             阶段表（9 段）+ 爆发时间轴（11 个真实窗口）
──────────────────────────────────────────────
证据条：runId · SimC 版本 · 路线 · 日期
```

**一条硬规则**：每段必须有一张图；没有图的段落降级成"表格 + 一句说明"，不允许纯文字段落。
段标题一律是「编号 + 一句话（这一段回答什么）」，写在图上面；图下面固定一句说明，说明不复述数字。

### 4.2 各段规格

| 段 | 组件 | 规格 |
| --- | --- | --- |
| 顶图带 | `Teaching/TopBand` | 三格：波次小图（整条路线逐波，本章档高亮）/ 一条数字结论（runId 配对）/ 该做什么（由 `rules.ts` 的 `burstAdvice` 判定，压成一行「N 只 › 30 秒 › 结论」，覆盖普通波 / BOSS / 无怪 / 节奏四种情形） |
| ① 模型卡 | `ModelCard` + `Teaching/WaveDiagram` + `Teaching/TargetBand` + `Teaching/ActionBudget` + `Teaching/CooldownWindow` | 四个数值 + 一句结论；方块数 = 该波实际怪数（keystone 路线），同色 = 同族；三步判断（几只 → 多久 → 开不开）已并入顶图带主行动格，不单独占位；有 trace 的 L1 章再加目标数轴与动作预算；L1-05 用两波冷却窗口代替目标数轴 |
| ② 主图 | `BurstChart` / `PriorityTableChart` / `SkillCards` / `LogStats` / `WaveTable` | 开 vs 不开必须两行各带真实 DPS，避免"绿色是增量还是全长"的歧义；表格类必须带 n、±CI、来源 |
| ③ 技能调整 | `PriorityDiff` | 只用「加 / 降」两列；每条一句话理由，理由必须能追到 APL 条件或 runId |
| ④ 地图 | `MapPanel` | 瓦片来自 `dist/maps/altar-of-fangs.webp`（keystone.guru 4×4 拼接）；逐波柱 + 横轴波次号 + 本章高亮。**路线没有坐标，所以不往图上标位置** |
| ⑤ 高手对照 | `CasePanel` + `Teaching/CastChart` + `Teaching/BurstTimeline` | L0 用整场施法次数（被动另列）；阶段日志给出阶段表和爆发窗口；红玉新生池使用 8 个 WCL Pull + 12 个虚空形态窗口；无数据时显示「待补 · 需要带 Fights 的导出」 |
| 证据条 | `EvidenceBar` | 常驻页面底部；列出 runId / 日志 / 来源 / 日期 |

阈值只写一处：`components/Teaching/rules.ts`（≥7 开 / 5–6 看冷却 / ≤4 不开 / BOSS 看下一波）。爆发增量不存常量，按目标档选 runId 后从 `numeric-summary.json` 计算。图、表、结论都从这里取，禁止各写一套。

### 4.2.1 图契约（2026-10-26）

五段是否真的有图，不再由“`.sec-fig` 里有没有子元素”判断。唯一清单是 `content/figures/chapters.json`：

| 状态 | 页面要求 | 门禁行为 |
| --- | --- | --- |
| `ready` | 必须有对应图/表，根元素带 `data-figure-kind` | 找不到图元 → `check:ui` 失败 |
| `missing` | 标出下一批与需要的数据，不装成已完成 | 两道门禁逐条警告，不阻塞 |
| `not-applicable` | 这一段本来就不该有图（如 L0 不绑定副本） | 不要求图 |

当前 60 段：55 有图 / 0 缺图 / 5 不适用；红玉第⑤段使用 8 个真实 Pull，L0-03 与 L1-01 的第五段使用模拟动作时间线，明确不冒充真人日志阶段。`check:ui` 从首页逐章点开 12 章，而不是只查 L1-02；`npm run verify:gates` 用坏样本证明门禁会真红。详见 `docs/figure-contract.md`。

### 4.3 状态

| 状态 | 表现 |
| --- | --- |
| 有模拟、无日志 | ⑤ 显示「待补」，其余正常 |
| 无路线 | ④ 显示「这一波来自通用模型，没有地图」 |
| 数值缺来源 | 整段不渲染，并在证据条标「此段缺来源，已隐藏」 |

## 4.5 多专精架构（界面层已就绪）

产品不再是"暗牧专用页面"，而是**一套模板 + 多个专精**。当前只有暗牧有数据，其余专精进去看到的是骨架预览。

| 层 | 实现 |
| --- | --- |
| 注册表 | `content/specs.json`：id / 职业 / 专精名 / 英雄天赋 / status（active·planned）/ baseline |
| 状态 | `state/spec.tsx`：`SpecProvider` + `useSpec()`，选择存 localStorage |
| 数据隔离 | `chaptersFor(specId)`、`allRuns(specId)`：非 active 专精返回空数组 |
| 顶栏 | 专精选择器（绿点=已实装，灰点=筹备中），点击切换，不新增导航项 |
| 空态 | `views/ComingSoon.tsx`：显式列出"会填进来什么 + 每块需要什么数据 + 接入三步" |

接入新专精不改界面，只做三件事：

1. 拿到该专精 SimC profile（含 APL）→ `scripts/sims-run.mjs` 出 runId
2. `scripts/apl-to-guide.mjs` 出优先级表、`scripts/leverage.mjs` 出杠杆
3. 按同一套 JSON 写 `content/chapters/*.json` → `npm run validate:content` 过门禁

把 `content/specs.json` 里该专精的 `status` 改成 `active` 即可上线。

## 5. 解析台（密度页）

**纵向六段，不是 tab**——和章节页同一套语言（段标题 → 图 → 一句说明），读者从上往下读完就是"结构 → 数量 → 构成 → 配装 → 参考资料 → 原始结果"。

| 段 | 回答的问题 | 数据 |
| --- | --- | --- |
| ① 谁依赖谁 | 谁依赖谁、谁在爆发里 | APL 条件（结构）+ 日志统计（占比） |
| ② 少它会掉多少 | 禁用一个技能掉多少 | 逐技能禁用 A/B（3000 迭代 × 2 场景） |
| ③ 伤害从哪来 | 伤害从哪来 | 基线模拟的 per-spell 统计 |
| ④ 换个输出模型，这件东西还值多少 | 属性收益曲线 + 预算内最优配比；武器附魔 / 武器油 / 美化 / 饰品 / 套装的贡献 | `content/analysis/stat-opt-archon.json` + `gearing-archon.json`（4 模型） |
| ⑤ 攻略是谁说的，我们验了什么 | 四家原文要点 + 一致项 + 分歧裁决 | `content/guides/sources-summary.json` + `crosscheck-archon.json` |
| ⑥ 原始结果在哪 | 原始结果在哪 | content/sims 全部记录（可按 runId 筛选） |

三张图的读法必须写在图下面：杠杆要写「统计显著 ≠ 实战关键」，伤害构成要写「占比 ≠ 重要性」。
`npm run check:ui` 会断言这里**没有 tab**、六段齐全。

## 6. 视觉规范（2026-10-26 改版：暗色）

参考WowCoach（可直接采样）与 Wowhead（CloudFront 403，按其公开设计语言：暗底 + 金色强调 + 高密度表格）。

实测 token（wowcoach.gg/connect，2026-10-26 采样）：

| 项 | 值 |
| --- | --- |
| 页面底色 | `#0b0e13`（rgb(11,14,19)） |
| 卡片底色 | `#0f1420`（rgb(15,20,32)） |
| 边框 | `#262b36`（rgb(38,43,54)） |
| 卡片圆角 | 16px；按钮圆角 8px |

本系统落地值（`apps/web/src/ui.css` 的 token，改这里就够了）：

| 项 | 值 |
| --- | --- |
| 字号 | 六档：`--fs-display` 36 / `--fs-title` 24 / `--fs-sub` 18 / `--fs-body` 16 / `--fs-meta` 14 / `--fs-caption` 12（图内 SVG 刻度字不算排版） |
| 栅格 | 内容宽 `--content` 1600；1440 视口下实测壳宽 1392、章节正文主栏 1168；卡片与段内图间距 `--gap` 16；首页、章节页、解析台共用 |
| 强调色 | 金色 `#f5c451`；正 `#4ade80`；负 `#f87171`；警示 `#fbbf24` |
| 数字 | 一律 `ui-monospace` + `tabular-nums`，右对齐 |

### 页面顺序（首页）

`hero（下一步 + 一个主按钮）→ 章节分组（主线）→ 一般教练建议（6 张卡）→ 数据状态条`

教练建议放在主线之后：它是"诊断"，不是学习路径的一部分，放前面会把 L0 → L1 → L2 的主线切断。

### 教练卡结构

`编号 → 标题 + 优先级标签（必修/建议/可选）→ 怎么做（绿色行动块，最显眼）→ 为什么（灰色）→ 证据 chip`

行动在前、解释在后：读者要的是"下一步做什么"。
