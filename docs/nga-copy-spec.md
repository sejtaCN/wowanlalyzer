## §1 NGA 精华攻略帖的共性语言特征

NGA 那篇《职业攻略撰写心得》把优秀职业攻略的品质拆成**逻辑、排版、措辞**三要素，并逐条给了正反例。把它和真实精华帖对上，本项目原文案的问题就很具体了。

### 1.1 用词习惯

- **结论前置，不铺垫**。原帖的核心主张是「增加实质性语句的占比：减少废话，书面化一点，就是减少非实质性语句」。它的反例是：
  > 那么，龙神附体在我们的循环里面占据了如此重要的地位，我们该如何选择龙神附体的用法呢？其实这是很简单的，首先，我们需要明确的是，龙神附体的 CD 比 120 秒团辅少了 10 秒，在不会损失使用次数的情况下，我们完全可以把龙神附体延后 10 秒到团辅期中……

  精简后只剩一句：
  > 龙神附体在循环中十分重要，由于它的 CD 比 120 团辅少 10 秒，在不会损失使用次数的情况下，可以把龙神附体延后 10 秒到团辅期中，让龙神附体后的爆发技能吃到团辅加成。

  **规律**：设问句、分析过程、评价性副词（「如此重要」「无疑」「其实很简单」）全部删掉，只留可执行的那部分。
- **书面化，但只书面化正文**。原帖点名要回避的词：「我们」「接下来」「我觉得」，以及「下一个是」这类视频口播衔接词。原话是：
  > 类似地，「我们」、「接下来」「我觉得」这种都是比较口语化的词语，在文字攻略中应当尽量少出现……对于职业攻略来说，如何构建循环更优秀是可以通过严谨的计算来得出的，因此，「我觉得」这样的词语不是很适合出现。
- **动词用实词**。「给」「铺」「挂」「留」「吃满」「摊薄」「轮不上」这类动词在 NGA 帖里密度远高于「进行」「实现」「达成」。本项目原文案的动词多是「使用」「保持」「考虑」「进行」。
- **数字直接写死**。NGA 帖不写「伤害提升比较明显」，写「提升约 12.7%」。本项目原有的数字精度其实很好，问题在于数字被埋在长句里。

### 1.2 段落组织

- **一段一件事**。原帖的排版篇要求「避免出现一大段文字的堆砌，合理分段；并且在出现一大段连续文字的时候，一定要用加粗或是变色来突出重点语句」。
- **并列一律列表**。原帖：「在列出多条并列内容的时候，用列表功能列出来」。
- **机器级细节折叠**。原帖：「将不是很重要，或者是多数玩家不关心也不需要理解的数值计算部分等用 collapse 功能折叠起来」。这条直接对应本项目把 APL 原文下沉到折叠区。
- **章节顺序固定**。原帖的逻辑篇主张按「读者第一次玩 → 已经熟练想优化」的顺序铺内容：先认基础，再讲机制，最后讲手法优化。NGA 真实帖的标准骨架是「前言/适用版本 → 技能介绍 → 优先级 → 起手/开荒 → 循环 → 常见误区 → 配装/天赋」。

### 1.3 语气

- **对读者说话，不对同行说话**。「你」用于操作指令，「我们」不用于结论。
- **边界感**：有数据限制就直说限制，不写免责套话。本项目原来的「需要带 Fights 的导出才能说『他这一波怎么做』」其实方向对，只是写成了开发口吻。
- **不夸大**。原帖后记强调「保证结论是正确的」，并建议找熟悉本职业的玩家校对。

### 1.4 标点与排版

- 句号收尾，不用省略号、不用感叹号。
- 并列用「、」或「；」，不用逗号连成长串。
- 数值与单位紧连：`30 秒`、`12.7M`、`43.98%`。
- 区间用短横：`5–9 只`、`10 只以上`。
- 条件写成贴紧阈值的形式：`目标 ≥5 只`、`间隔 <122.4 秒`。
- 关键词加粗或变色，其余留白。

### 1.5 本项目原文案与它的差距（实测）

| NGA 规律 | 本项目原文案 | 判定 |
|---|---|---|
| 删设问与套话 | 5 段 note 全是「结论 + 补充 + 免责」三段式，以分号并列收尾 | 违反 |
| 结论前置 | 多句把结论放在后半句 | 违反 |
| 书面化，禁「我们」 | 「我们」出现在解析台与来源页 | 违反 |
| 并列用列表 | 条件列整段挤成一个单元格 | 违反 |
| 机器细节折叠 | APL 原文直接铺在正文里 | 违反 |
| 数字写死 | 数字精度合格，但与结论之间隔太多字 | 部分违反 |

## §3 四类内容的对齐表达规范

> **规范已上移**：四类内容的结构骨架、必填要素、用词规范，以
> `docs/guide-content-rules.md` §3 为准（那是唯一规范源，跨专精通用）。
> 本节保留的是**这次暗牧改写的落地实证**——每类内容改前的原样与改后的成稿，

### 3.1 图表与数据描述

**结构**：动作结论 → 数值 → 阈值 → 怎么读。

| 要求 | 落地方式 | 例 |
|---|---|---|
| 标题写「读者看完要知道什么」 | 不写「这是什么图」 | `整场读数：持续伤害覆盖了几个目标、爆发开了几次`（原：`他这一场的整场读数`） |
| 结论前置 | 动词开头 | `4 只以下不开爆发。一次只换 4.93M，不到大波的 39%——把冷却留给下一波。` |
| 数值保留精度 | 不二次四舍五入 | `9.3–11.6M`、`43.98%`、`155.6 秒` 原样保留 |
| 导读指出看哪里 | 段导读点名柱 / 列 / 行 | `开与不开差 44.0%，一次爆发多换 12.7M。保守误差上限 ±0.32%，别把它当收益。` |
| 阈值写清 | 贴紧阈值 | `目标 ≥5 只`、`间隔 <122.4 秒` |
| 误差要交代 | 明说是误差 | 同上 |

### 3.2 技能介绍

**结构**：定位 → 机制要点 → 适用场景 → 收益。四件事说清，不重复。

| 要求 | 落地方式 | 例 |
|---|---|---|
| 技能名只写中文 | 英文键移到悬停 `title` | 技能卡现在只显示「触须猛击」，鼠标悬停才显示 `tentacle_slam` |
| 有出处的用中文 | `skills.json` 为准 | 25 个技能全部有中文名 |
| 没出处的框成标识符 | 「」包裹 | `「devour_matter」天赋` |
| 条件写成人话 | APL 条件逐条翻译 | `吸血鬼之触没在跳 且 目标剩余存活 ≥ 10 且 已挂吸血鬼之触的目标数 < 5` |
| 分支条件给阈值 | | `间隔小于 122.4 秒才二选一，给大波；122.4 秒以上两波都能开` |

**APL 条件生成规则**（`scripts/apl-to-guide.mjs`）：

1. 先按顶层 `|` / `&` 拆出「或」分支和「且」项，括号内的嵌套保留成 `（A 或 B）`——逻辑结构与 APL 一一对应。
2. 每个叶子单独翻译，否定用规则内的负向说法（`没在跳` / `没有…增益` / `没点…天赋` / `没置位`）。
3. 技能键 → 中文名（取 `skills.json`）；天赋 / buff / 变量名查不到中文就用 `「标识符」`。
4. 运算符写成 `≥ ≤ = ≠`，`*` 写成 `×`。
5. 输出两份：`conditionZh`（整串）与 `conditionGroups`（顶层「或」的每一支，前端渲染成可扫读的短语行）。

### 3.3 技能优先级

**结构**：分级（两档）→ 理由（条件 → 结论）→ 依据（人话 + APL 原文）→ 条件分支。

| 要求 | 落地方式 | 例 |
|---|---|---|
| 只有加 / 降两档 | 序号 = APL 表真实位置 | `#1 / #2 / #3` |
| 理由一条一句 | 条件 → 结论，不反问 | `只有残血目标才进循环，中波轮不上它` |
| 条件分支写清阈值 | | `目标 ≤2 时 AoE 循环不启动，填充技能重新有用武之地` |
| 人话与原文并列 | 原文进折叠区 | 依据行下方新增「APL 原始写法」折叠条 |
| 依据不写串 | 门禁校验 evidence ↔ raw | 见 §6 |

**依据与原文的对应关系**（33 条逐条核对过）：

- 人话依据 = 原条件的中文翻译，不加解释、不加结论。
- APL 原文进 `raw` 字段，UI 折叠展示，**信息一条不丢**。

**三个标签各指什么**（初版两个都叫「APL 原文」，读者会以为依据行里是裸代码，实则已是中文，
本轮把它们分开）：

| 标签 | 指什么 | 出现在哪 |
|---|---|---|
| `APL 条件：` | 机器条件的中文翻译 | 依据行的开头 |
| `APL 原始写法` | 机器语法原文 | 依据行下方的折叠条标题 |
| `APL 原文` | 泛指机器语法 | 本文档叙述里（不作为界面标签） |
- 两条依据不允许共用同一句话（门禁校验）。

### 3.4 可视化部分

**结构**：这张图看什么 → 怎么读 → 边界在哪。

| 要求 | 落地方式 | 例 |
|---|---|---|
| 先说看什么 | 段导读首句 | `柱高就是这一波的实际怪数。点任意一波，上面的结论、下面的数值、地图注记会一起换。` |
| 再说怎么读 | 位置 / 颜色 / 数量含义 | `两行各自是真实 DPS 和 95% CI。增量没有叠在原条上。` |
| 流程用箭头 | 顺序编号 | `① 认规则 → ② 分波次 → ③ 进路线` |
| 界面指引说清点哪 | | `点任意一波，上面的结论、下面的数值、地图注记会一起换` |
| 没坐标不标坐标 | 明说 | `路线没有每波坐标，这张图只给地形，不标位置。` |
| 没分段不假装有 | 明说 | `整场日志推出的阶段，不是单波。这份导出没有死亡事件，切不出「第 N 波几时开始」。` |

### L0-01 暗牧在做什么

- **副标题**：下一个 GCD：继续铺持续伤害，还是进爆发
- **图题**：整场读数：持续伤害覆盖了几个目标、爆发开了几次
- **优先级·加**｜吸血鬼之触：第一个 GCD 就给它，别等怪聚齐
  - 依据：APL 条件：「actions.main」里，吸血鬼之触排在填充技能之前
- **优先级·加**｜暗言术：痛：第二个持续伤害，跟上一条一起铺
  - 依据：APL 条件：已挂暗言术：痛的目标数 ≥ 已挂吸血鬼之触的目标数，作为补充条件
- **优先级·降**｜精神鞭笞：它是填充。持续伤害没铺满时，不要拿它换刷新
  - 依据：APL 条件：「actions.main」里，精神鞭笞排在所有持续伤害之后
- **对照**：整场读数：不是某一波，是全场
  - 吸血鬼之触覆盖 4.91 个目标，暗言术：痛 4.68 个。他不是单目标打法。
  - 11 次虚空形态，持续中位 35.5 秒。
  - GCD 中位 0.95 秒，每分钟 85.9 次施法。
  - 证据：来源：WCL 事件表 CSV（88 个文件 / 25,152 条事件）。这份导出没有战斗分段，拆不到单波。

## §5 所用风格特征的简要说明

以下是实际采用的写作规律，每条都是可直接执行的判据。

| 维度 | 规律 |
|---|---|
| **句子** | 结论前置；动词开头；正文不出现「我们 / 接下来 / 我觉得 / 下一个是」；不写设问与分析过程；句号收尾 |
| **段落** | 一段一件事，2–4 行；并列用列表；机器级细节折叠 |
| **用词** | 动词用实词（给 / 铺 / 挂 / 留 / 吃满 / 摊薄 / 轮不上）；不用评价性副词；不给自造官方译名 |
| **语气** | 对读者说话，操作指令用「你」；有数据限制就直说限制，不写免责套话 |
| **标点** | 数值与单位紧连（`30 秒` / `12.7M` / `43.98%`）；区间用短横（`5–9 只`）；并列用「、」「；」；阈值贴紧写（`目标 ≥5 只`） |
| **数字** | 保留原始精度；不二次四舍五入；保守误差上限要标明是误差 |
| **专名** | 有出处的用中文（技能名取 `skills.json`）；没有官方中文名的天赋 / buff / 变量保留英文标识符并用「」框住 |
| **图表** | 标题写「读者看完要知道什么」；导读指出看哪根柱 / 哪一列 / 哪一行 |
| **技能** | 定位 + 机制要点 + 适用场景 + 收益，四件事说清；英文键只进悬停提示 |
| **优先级** | 只有「加 / 降」两档；理由一条一句，句式是「条件 → 结论」；分支写清阈值；人话与 APL 原文并列，原文进折叠区 |
| **可视化** | 先说看什么，再说怎么读；流程按顺序编号用箭头；没坐标不标坐标，没分段不假装有分段 |
| **禁区** | 不出现开发中间文字（路径、脚本名、批次、待补说明）；不出现字面 markdown 标记 |

## §6 门禁与验收

### 新增 `npm run check:copy`

按「读者层级」分级扫描：

| 层级 | 范围 | 违规判定 |
|---|---|---|
| 攻略正文 | `content/chapters/*.json` 的标题 / 副标题 / 结论 / 图题 / 优先级理由与依据 / 对照文案 | 错误 |
| 章节页组件 | `apps/web/src/components/**/*.tsx` | 错误 |
| 应用层 | `apps/web/src/views/**/*.tsx`（工具页、骨架页） | 提醒 |

检查项：

1. 禁用词（开发中间文字、字面 markdown `**`）→ 错误
2. AI 腔词 → 提醒
3. 机器标识符未用「」框住 → 错误
4. 未本地化拉丁字符（不在白名单、未被「」框住）→ 错误
5. 一句里 3 个以上分号（三段式套话）→ 提醒
6. 字段长度超预算 → 提醒
7. **同一优先级组里两条依据共用同一句话，但 APL 原文不同 → 错误**（依据写串）
8. **依据与自己的 APL 原文对不上 → 错误**（依据张冠李戴）

当前状态：**0 条错误 / 9 条提醒**（9 条全在应用层与来源页，属本轮范围外）。

### 新增 `npm run check:doc`

§4 是交付文档里「重写后的完整攻略正文」的正式版本，读者按它读；代码里跑的是
`content/chapters/*.json`。两边一旦漂移，文档就在骗人——而本轮术语改名（「APL 原文」
→「APL 条件」）时正是 JSON 改了、文档没改，21 条依据当场对不上。这个门禁按 §4
的语法逐条对：

| 文档结构 | 对应 JSON 字段 | 判据 |
|---|---|---|
| `- **副标题**：` | `subtitle` | 逐字相等 |
| `- **结论**：` | `claim` | 逐字相等 |
| `- **图题**：` | `chart.title` | 逐字相等 |
| `- **优先级·加/降**｜` | `priorityDiff.add/drop[]` | 组内按序 zip；行以 `reason` 结尾且技能名前缀非空；下一行「依据：」逐字等于 `evidence` |
| `- **对照**：` | `casePanel.headline` | 逐字相等；下面每条对应 `points` / `evidence` / `reading` |
| `- **缺对照**：` | `casePanel.reason` | 逐字相等 |

顺带扫 §4 的乱码（U+FFFD）与多余的章节块。

回归验证：把 `l0-01` 的一条 `reason` 改短一个字，门禁立刻报
`「优先级·加」第 1 条与 JSON 的 reason 对不上`；还原后恢复通过。
