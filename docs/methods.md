## 一、优先级的两层量化：联动与杠杆

> 页面：解析台 → 纵向六段里的「联动」「杠杆」「伤害构成」

### 1. 为什么需要两层

一张优先级表只回答"谁先谁后"，回答不了两个更要紧的问题：

- **为什么**排在前面？（它依赖什么、触发什么）
- 排前面**值多少**？（少它会掉多少 DPS，还是无所谓）

于是拆成两层：**联动**解释结构，**杠杆**给出数量。

### 2. 联动：谁依赖谁

两类边，来源分开标注，不混：

| 边 | 来源 | 口径 |
| --- | --- | --- |
| 依赖 DoT / Buff | APL 条件 | `dot.x.ticking`、`buff.x.up` 等直接来自 profile，可复现 |
| 爆发内占比 | 真实日志 | 该技能施法落在虚空形态窗口内的比例 |
| 爆发起手 | 真实日志 | 爆发窗口前 3 秒内出现的技能 |

读图方式：左列是 DoT / Buff，中列是技能（括号里是爆发内占比），右列是虚空形态。线越粗，占比越高。

当前联动图使用红玉新生池样本的 1,536 个完整 DoT 区间，并按「DoT 开始前 0.6 秒内、施法目标同名」归因“谁挂上了这个 DoT”。

### 3. 杠杆：少它会掉多少

做法：把某个技能在 APL 里的所有动作行注释掉，其余不动，重跑同一场景（3000 迭代，单体 300 秒 / 5 目标 30 秒），比较 DPS。

结果（执政官，单体 300 秒，基线 231,256）：

| 技能 | 禁用后 | 基线伤害占比 | 结论 |
| --- | ---: | ---: | --- |
| 暗言术：痛 | **−48.04%** | 5.6% | 贡献远大于它的伤害占比——它还是别的东西的前置 |
| 暗言术：癫 | −30.42% | 18.5% | 主力输出 |
| 精神鞭笞：狂 | −22.74% | 8.1% | 高杠杆填充 |
| 虚空齐射 | −22.73% | 12.4% | 与占比相当 |
| 触须猛击 | −20.17% | 3.7% | **占比低但杠杆高**：它在替吸血鬼之触续 |
| 虚空形态 | −19.59% | 无直接伤害 | 增益类，但禁掉照样掉 |
| 精神鞭笞 | −14.62% | 11.0% | 填充也有量 |
| 光晕 | −13.49% | 1.5% | 占比 1.5% 却值 13.5%——它给的是增伤与触发 |
| 心灵震爆 | −8.51% | 13.1% | 占比高但杠杆低（可被替代） |
| 能量灌注 | −5.18% | 无直接伤害 | 增益类 |
| 暗言术：灭 | −0.23% | 1.2% | 几乎不影响单体 |
| 吸血鬼之触 | **+0.03%（误差内）** | 3.5% | **禁掉也不掉**：触须猛击一直在替它上 |
| 虚空洪流 / 虚空冲击 | ≈0 | — | 本配置没点（虚空编织技能） |

#### 两场景对照（同一技能，在不同波次模型里的杠杆）

| 技能 | 单体 300s | 5 目标 30s | 两个场景差多少 |
| --- | ---: | ---: | ---: |
| shadow_word_pain | −48.04% | −35.12% | 12.92 个百分点 |
| shadow_word_madness | −30.42% | −27.89% | 2.53 个百分点 |
| mind_flay_insanity | −22.74% | −18.38% | 4.36 个百分点 |
| void_volley | −22.73% | −17.46% | 5.27 个百分点 |
| tentacle_slam | −20.17% | −30.26% | 10.09 个百分点 |
| voidform | −19.59% | −29.79% | 10.20 个百分点 |
| mind_flay | −14.62% | −3.53% | 11.09 个百分点 |
| halo | −13.49% | −17.45% | 3.96 个百分点 |
| mind_blast | −8.51% | −2.96% | 5.55 个百分点 |
| power_infusion | −5.18% | −7.38% | 2.20 个百分点 |
| shadow_word_death | −0.23% | −0.18% | 0.05 个百分点 |
| void_torrent | 0.02% | −0.07% | 0.09 个百分点 |
| vampiric_touch | 0.03% | −0.17% | 0.20 个百分点 |

**读法**：触须猛击在 5 目标里更值钱（−30.3% vs −20.2%），虚空形态也是（−29.8% vs −19.6%）；
反过来暗言术：痛在单体里更值钱（−48.0% vs −35.1%）。心灵震爆、精神鞭笞在 5 目标里几乎可以忽略（−3% 上下）。
**这说明"技能重要性"不是常数，而是随波次模型变化**——这正是按波次模型分章的理由。

#### 三条可以直接写进课件的结论

1. **伤害占比 ≠ 重要性。** 光晕占 1.5% 伤害，禁掉掉 13.5%——它通过增伤和触发在起作用。反过来心灵震爆占 13.1%，禁掉只掉 8.5%。
2. **吸血鬼之触不用手动补。** 禁掉「吸血鬼之触」这个动作只损失 0.03%（在误差内），因为触须猛击在持续续 Dot。这和之前 VT 阈值 A/B 的结论一致（当时是"不绑定"）。
3. **暗言术：痛是隐藏地基。** 只占 5.6% 伤害，禁掉却掉 48%——说明它同时驱动了别的机制（心智联接等）。

### 4. 与三个网站的关系

网站给的是"顺序"，我们给的是"顺序背后的量"。当网站之间顺序不一致时（例如虚空齐射排第 6 还是第 12），用杠杆数据判断：如果两种排法的差别小于误差带，就不必纠结；差别显著，就按我们的数字来，并把依据写进页面。

## 二、从日志推断阶段（高手对照的真实性说明）

> 日志：`content/logs/xiaohuasheng-events.json`（WCL 事件表 CSV，88 文件 / 25,152 事件 / 29 分钟）

### 1. 需求拆解

目标：把「整场统计」变成「分阶段统计」，让页面能说"他这一段开了几次爆发"，而不是"他整场开了 11 次"。

需要回答三个问题：

| 问题 | 能不能答 | 依据 |
| --- | --- | --- |
| 这一段打的是哪个区域 / 哪个 BOSS | ✅ 能 | 怪物族组成 + BOSS 名 |
| 这一段开了几次爆发、节奏多快 | ✅ 能 | 虚空形态 buff 窗口 + 施法时间戳 |
| 这是路线的第几波 | ⚠️ 只能给重合度 | 与路线波次的怪物族集合比对 |
| 单独一波的起止（路线 15 波） | ❌ 不能 | 见 §4 |

### 2. 数据里有什么

- 2,499 条施法（时间、技能、目标）
- 其中 1,021 条带敌人目标，覆盖 **16 个怪物族**
- 11 个虚空形态窗口（起止时间）
- 四类持续伤害的施法记录

目标名带数量后缀，去掉后缀就是怪物族名，例如 `Venom Leech 8` → `Venom Leech`。
日志里的敌人是 `Rav'i` 和 `Zul'jan`——正是 Altar of Fangs 的两个 BOSS，**所以这场就是他打这张图的记录**。

### 3. 方法

1. **族团**：按 30 秒窗口统计怪物族共现，得到 4 个区域族团 + 2 个 BOSS 族：

   | 族团 | 怪物 |
   | --- | --- |
   | 入口祭坛 | Ritual Chieftain、Primal Serpent、Twinfang Harrower、Ravenous Descendant、Venom Leech |
   | 深处 | Rattling Writhe、High Evolutionist、Bloodletter、Hatchling |
   | 盘绕回廊 | The Writhing Coil、Uncoiled Writhe |
   | 上层平台 | Blade of the Altar、Ula'tek's Chosen、Ascendant Serpent |

2. **分桶投票**：5 秒一个桶，按族团事件数投票得到"主导族团"；3 桶中值滤波抑制抖动。
3. **合并**：连续同主导合并成阶段；短于 30 秒并入相邻；A-B-A 抖动合并。
4. **BOSS 单独成段**：BOSS 族出现的时间段从区域段里切出来。
5. **指标**：时长、族、敌人施法数、每分钟施法、该段内开启的爆发次数、爆发覆盖秒数。
6. **路线对应**：该段怪物族集合与路线每一波的 Jaccard 重合度，只取最高的一波。

### 4. 为什么不能切到「单波」

试过四种信号，都不成立：

| 信号 | 结果 |
| --- | --- |
| 施法空档（时间间隙） | 带目标施法间隔中位 **1.27 秒**；大于 8 秒的空档全程只有 **12 个** |
| 活跃敌人集合清空 | 全程**一次都没有清空**（他一直在打，连拉） |
| 怪物个体编号 | 编号会复用：`Venom Leech` 只出现 10 个不同编号，却编到 22 号 |
| 新目标成批出现 | 10 秒桶里最多 7 个，多数桶是 1–2 个，无法定界 |

根因：这份导出**只有施法/增益/减益，没有死亡事件**，也没有战斗分段。单个怪什么时候死、这一波什么时候结束，数据里没有。

要切到单波，需要下面任一种导出：

- WCL 的 `Fights`（战斗分段）表；
- 带 `UNIT_DIED` 的战斗日志（`WoWCombatLog.txt`）。

### 5. 结论（页面正在用的）

他这一场的 9 个阶段，爆发分布 **2 / 2 / 1 / 2 / 0 / 2 / 0 / 0 / 2**：

| # | 阶段 | 时长 | 爆发次数 |
| --- | --- | --- | --- |
| 1 | 入口祭坛 | 410s | 2 |
| 2 | ★ BOSS 1 · Rav'i | 260s | 2 |
| 3 | 深处 | 195s | 1 |
| 4 | 盘绕回廊 | 210s | 2 |
| 5 | 深处 | 80s | **0** |
| 6 | 上层平台 | 230s | 2 |
| 7 | 上层平台 | 60s | **0** |
| 8 | 入口祭坛 | 30s | **0** |
| 9 | ★ BOSS 2 · Zul'jan | 250s | 2 |

三个零爆发的阶段加起来 170 秒。**但不能据此说“冷却没转好”**：同一套 SimC 的相邻虚空形态起点间隔只有 121.2–122.4 秒；L1-05 已改成按两波间隔判，155.7 秒只是他的爆发节奏，不是具体两波间隔。日志没有死亡事件，不能给某一次小波贴冷却标签。

### 3. 三家不一致的（以及怎么处理）

#### 3.1 虚空齐射的位置：Method 说最后，Maxroll/NGA 说第 6

- Method：第 12 位（暗言术：灭之后）
- Maxroll / NGA：第 6 位（癫之后、灭之前）
- **我们自己的 APL（Archon profile）**：两条独立条件——
  - `cooldown.voidform.up` 时用；
  - 无共振能量 / 虚空形态就绪 <60s / 虚空形态中 / 有共振能量增益 / 碎虚 ≥4 层 时用。

**判定：不是真矛盾。** 人类列表必须摊成一行，APL 用条件分裂。教学里写「爆发窗口内优先」，不写死第几位。状态：`resolved_by_apl`。

#### 3.2 触须猛击：Method 给两个位置，Maxroll/NGA 并入 DoT 行

APL 里同样是三处（补 DoT、可刷新时补、距下次加怪 >30/20 时泄充能）。**一致**，只是 Method 写得更细。

#### 3.3 暗言术：灭：Method 排第 11，Maxroll/NGA 排第 7

触发条件三家完全一致（<20% / 吸收盾）。灭是条件技能，位置差异在实战里由条件决定。状态：`low_impact`。

#### 3.4 术语：Voidform 还是 Void Eruption

Method 写 Voidform，Maxroll/NGA 写 Void Eruption（虚空爆发）。指的是同一次爆发：**Void Eruption 是让你进入 Voidform 的那一下**。教学统一用「虚空形态（Voidform）」，起手步骤注明按 Void Eruption。

#### 3.5 套装描述不完全一致

- Method：4 件套给免费虚空齐射。
- Maxroll：2 件套 = 触须猛击冷却 -3s、伤害 +100%；4 件套 = 触须猛击给一次免费虚空齐射。

Maxroll 写全了，Method 只写了 4 件套。**待用 SimC profile 的套装字段复核**。

## 四、配装与属性最优化（2026-10）

> 页面：解析台 →「换个输出模型，这件东西还值多少」
> 数据：`content/analysis/gearing-archon.json`、`content/analysis/stat-opt-archon.json`
> 生成：`npm run gearing`、`npm run statopt`

### 1. 为什么要分开测：两件事不是一回事

- **某件东西值多少**（附魔/美化/饰品/套装）：从 profile 里摘掉它再跑，看掉多少。
- **属性怎么分配**：总评级固定，四项之间换——这是约束优化，不是查表。

### 2. 口径（都是实测出来的，不是猜的）

| 项 | 做法 |
| --- | --- |
| 附魔范围 | 只看**武器**（用户口径）；头/肩/胸/腿/戒指附魔不进分析 |
| 美化 | crafted 装备上的 `bonus_id`（本 profile 在手腕 + 腰），摘掉即算整套贡献 |
| 套装 | `set_bonus=midnight_season_2_4pc=0` / `..._2pc=0` 关掉再跑（`disable_set_bonus` 是无效选项） |
| 改属性 | 只能 `gear_<stat>_rating=<绝对值>`；命令行 `haste_rating=` 会被静默忽略 |
| 预算 | 同一测试 profile 的四项评级合计 **3209**（暴 380 / 急 1282 / 精 1424 / 全 123），只作为四模型共用的测试尺度，不表示玩家当前面板 |
| 曲线 | 把全部预算压到一个属性（25/50/75/100%），其余归零，每点真跑 |
| 优化模型 | 乘区近似：`DPS ≈ DPS(全零) × Π 曲线(i)/DPS(全零)`（可加模型低估 8.5%，弃用） |

### 4. 固定预算下的最优配比（2000 迭代，预算 3209）

| 输出模型 | 暴击 | 急速 | 精通 | 全能 | 实测 DPS | 相对固定基线 | 预测误差 |

1. **全能在这个固定测试模板里收益最低**：四次优化都把它压到最低（9），差额挪给暴击/急速/精通。

- 曲线到"全压一项"为止，超过预算的堆叠没测。

## 五、动作预算与资源采样（2026-10-26）

> 页面：L1-01/02/03/04/06 第①段「这一档有多大，时间怎么花」
> 数据：`content/analysis/play-budget-archon.json`、`content/sims/trace_archon__*.json`
> 生成：`npm run sims:trace && npm run analysis:budget`

### 1. 怎么读

- **DPS 来自全部迭代**（5000，报告 95% CI）；**动作序列与狂乱值只来自一次代表迭代**，不是 5000 次的平均动作表。
- **GCD 起手点**按不同动作起始时间去重：药水、饰品、能量灌注会和别的动作同一时刻发生，不重复算一个 GCD。
- **起手间隔中位**是观测到的相邻起手点间隔，不是理论 GCD；急速、施法/通道都会影响它。
- **狂乱值**是动作执行后的采样值。观测回复 / 消耗 = 相邻采样上涨 / 下降之和；采样没触顶不代表没有溢出。
- 技能角色只用于数动作：DoT / 续 Dot、填充 / 直伤、爆发 / 增益、药水 / 饰品；不是伤害占比。
- trace 用 `seed=104729` + `threads=1` 跑，重跑动作序列和数值可复现；DPS 的样本数会比迭代数少 1（首迭代热身）。

### 2. 实测（5000 迭代；动作为代表迭代）

| 场景 | 动作 | GCD 起手点 | 起手间隔中位 | DoT / 填充 / 爆发 / 物品 | 狂乱 起始→结束（峰值，消耗次数） |
| --- | ---: | ---: | ---: | --- | --- |
| 2 目标 30s | 42 | 39 | 0.756s | 13 / 24 / 3 / 2 | 6→37.9（58.2，7 次） |
| 5 目标 30s | 42 | 39 | 0.755s | 16 / 21 / 3 / 2 | 6→38.8（64.0，7 次） |
| 8 目标 30s | 40 | 37 | 0.757s | 18 / 17 / 3 / 2 | 6→42.6（61.0，6 次） |
| 4 目标 12s（ADD 近似） | 19 | 16 | 0.755s | 5 / 9 / 3 / 2 | 6→14.8（56.9，3 次） |
| BOSS 单体 90s | 99 | 96 | 0.871s | 28 / 65 / 4 / 2 | 6→30.9（75.4，18 次） |

### 3. 目标放大：同一轮爆发每多一只值多少

用同场景的 5/6/7 目标 A/B 直接相减，不做外推：

| 档位变化 | 单次爆发增量 | 每多 1 只 |
| --- | ---: | ---: |
| 5 → 6 只（30s） | +1.16M | +1.16M |
| 6 → 7 只（30s） | +1.09M | +1.09M |
| 7 → 8 只（30s） | +1.16M | +1.16M |

读法：目标数从 5 到 8，单次爆发从 9.30M 涨到 12.71M。这是**同一轮冷却换回的伤害**，不是“每只怪值多少 DPS”；超过 8 只模拟上限后不继续外推。

### 4. 限制

- 木桩是满 uptime，没有走位、转火、打断；这 30 秒是时间上限，不是副本里的可用时间。移动 0–3 秒、危险点 3 个没有折算，不能拿这张图直接扣 GCD。
- 狂乱只有动作采样，没有事件级跳数；`samplesAtCap = 0` 只表示采样点没碰到 100，溢出量仍缺。
- 4 目标 12 秒是「3 只小怪 + 主目标」的近似，模型偏乐观；只比窗口内外的相对差，不报绝对 DPS 结论。
- L1-05 的「大波后接小波」需要同一场里的配对窗口，当前 trace 是一次独立战斗，不硬凑。

### 5. 同批修正：爆发 A/B 的英雄天赋来源

旧的 `dec_*` 爆发 A/B 文件没有记录专精来源，生成脚本实际用的是 **Voidweaver** 底稿，文档却按 Archon 引用。2026-10-26 已把全部 `dec_*` 用 Archon profile 重跑，并写入 `hero / profileId / profileFile`；同场景 8 目标 30 秒从旧的开 1.32M / 不开 0.98M，变为开 1.387M / 不开 0.963M。页面上所有 `dec_*` 增量已随重算更新。

这条修正也改了一个结论：BOSS 单体 90 秒一次爆发 5.15M，**高于** 2 目标 30 秒的 4.93M，所以 BOSS 的文案从「不开」改成「看下一波」——它低于任何大波，但不是绝对空窗。`rules.ts`、L1-04、L2-01 已同步。

## 六、两波间隔与冷却窗口（L1-05）

### 1. 口径

- **观测冷却上限 122.4 秒**：取 300 秒单体 / 3 目标动作序列里相邻虚空形态施法起点的最大间隔（4 个间隔，121.2–122.4s）。这是本 profile 的观测值，不是技能说明里的理论冷却。
